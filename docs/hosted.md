# Hosted adapter

The multi-user add-on at `https://stremio.chill.institute`. chill-web issues
each account's add-on link at `/stremio`; the link carries an Engine-issued
credential that the adapter forwards to Engine on every call. The adapter keeps
no database, key, installation registry or management API. For isolated
single-user probes, use the [local adapter](./adapter.md).

## Run

```sh
CHILL_PUBLIC_ORIGIN=http://127.0.0.1:7000 mise run hosted:serve
```

[hosted-run.ts](../src/hosted-run.ts) owns the configuration schema.

- `CHILL_PUBLIC_ORIGIN` must be the exact external origin; Host is checked
  against it. Set `CHILL_LISTEN_HOST=0.0.0.0` only behind the HTTPS ingress.
- `CHILL_WEB_ORIGIN` sets the chill-web origin for `/configure`, the root
  redirect and reconnect notices; `CHILL_ENGINE_BASE_URL` overrides Engine.
- Status clips are generated by setup or the image build
  ([status-media.ts](../scripts/status-media.ts)); runtime only loads them.
- The [Dockerfile](../Dockerfile) image is non-root and bakes the release
  version into the manifest (`CHILL_ADAPTER_VERSION`; local runs report
  `0.0.0`). Run it with a read-only root filesystem, no capabilities and no
  volume. SIGTERM cancels open requests.
- The process never logs paths, headers, credentials or upstream bodies.
  Ingress must suppress access logs for this service, since paths carry the
  credential and playback URLs are provider grants. No request capture,
  analytics or third-party scripts on add-on or playback surfaces.
- `GET /health` checks only process liveness and ignores capacity.

## Capacity

[admission.ts](../src/admission.ts) admits 64 units per process and 16 per
add-on link: one per open request and one per submission until Engine answers.
16 covers one link browsing and playing on two synced devices, since Stremio
fires every catalog request at once and never cancels them.

- Over the process limit: `503 unavailable`. Over the link limit: `429
  resource_exhausted`, except selected media under `/play/` and `/status/`,
  which gets `503` because HLS players retry 5xx only. All carry
  `Retry-After: 5`. An Engine rate limit on selected media is also `503`,
  without `Retry-After`.
- A new selection needs two free units or it submits nothing; an `owned:` row
  needs one, which a [waiting](#videos-already-in-putio) request holds for at
  most 35 seconds.
- `/health`, HEAD and OPTIONS never count; `/notice/` counts only toward the
  process limit. Counts are per process, keyed by a credential hash.

## Add-on links

- Personal: `https://stremio.chill.institute/s/<credential>/manifest.json`.
  The credential is an opaque PASETO `v4.local.` token with an optional key-ID
  footer. [credential.ts](../src/credential.ts) checks only shape and length;
  a malformed one gets `404` without calling Engine.
- Engine calls send `X-Chill-Stremio-Credential`, never `Authorization`.
- Anyone with the link can browse the library, play and start downloads. Stremio
  prints the full link in its install dialog; never share that screen.
- Engine `401`/`403` shows a **Reconnect chill.institute** row or source and
  plays the `reconnect` clip, all pointing to `https://chill.institute/stremio`.
  Exceptions: a `403` on the [season lookup](#season-packs) and any error on the
  [owned-video lookup](#videos-already-in-putio) only drop their rows.
- Public listing: `https://stremio.chill.institute/manifest.json` requires
  configuration and carries no credential. `/configure` is a static page with
  no scripts that links to chill-web. Submit only this URL to Stremio's
  [publishing form](https://stremio.github.io/stremio-publish-addon/index.html),
  never a personal link; confirm it in the
  [community catalog](https://api.strem.io/addonscollection.json) (up to 24
  hours).
- [manifest-descriptions.ts](../src/manifest-descriptions.ts) holds both
  manifest descriptions and stays package-free: `hosted:public` imports it with
  Node alone and requires an exact match with the deployed adapter.

## Library

**put.io library** lists the whole account from the root, breadth-first, and
rechecks membership per request within a 10-second deadline. Traversal stops at
5,000 entries per folder, 50,000 in total, 1,000 folders or 64 levels and then
errors instead of returning a partial page. A video put.io must
[convert](#videos-putio-must-convert) lists a **Convert and play from put.io**
source; one still preparing lists **Play from put.io**. Both wait in the
player as [owned rows](#videos-already-in-putio) do. Library videos carry
Engine's subtitle tracks; release playback has none, so reopen the file from
the library for subtitles.

## Selected media

Listings, HEAD, OPTIONS and prefetch hints are read-only. GET on
`/s/<credential>/play/<type>/<id>/<release>.m3u8` looks the release up again
with `Search` (or a [season pack](#season-packs) with
`GetTVShowSeasonDownloads`) and submits it with `AddTransfer`. A release that
search no longer lists, or whose indexers fail, plays `release-unavailable`.
Legacy `.mp4` selections get `404`, or `503` on indexer errors.

- **One submission.** Identical requests share a submission while any is open
  and for 60 seconds after; an error before any transfer is not kept. Later
  selections submit again and Engine returns the existing transfer unless it
  failed or its file is gone. The submission has its own 41.5-second budget, so
  a wait window ending first redirects with the next `wait=<n>` and rejoins it.
  A failed, lost or timed-out submission response is never retried and plays
  `unknown`.
- **Engine refusal codes** (`Chill-Error-Code`): `stremio_folder_missing` plays
  `reconnect` (a new link binds an existing folder); `putio_rate_limited` and
  `invalid_transfer_url` play `release-unavailable`; anything else, including
  `putio_rejected`, plays `unknown`.
- **Waiting.** A pending transfer (including put.io's `COMPLETING`, or a video
  put.io still types as a plain file) redirects to
  `/s/<credential>/status/<transferId>.m3u8?wait=<n>`, or
  `.../status/<transferId>/<season>/<episode>.m3u8` for a pack. Status URLs
  never submit. HLS waits 25-second windows, legacy `.mp4` 45, up to five
  redirects. After four minutes, or the fifth status redirect, HLS plays the
  pending clip; legacy `.mp4` returns `503 download_pending`. Stremio for Linux
  reaches the clip about 150 seconds in, after the reuse window, so selecting
  again submits again.
- **Clips.** Terminal states redirect to a five-second
  `/s/<credential>/notice/<state>.m3u8`; states and wording live in
  [status-media.ts](../src/status-media.ts). Clip routes never call Engine.
- **File choice.** A multi-file download plays only when exactly one video is
  not a sample (last name word `sample`, or under a `Sample`/`Samples` folder);
  otherwise, or past listing limits, it plays `select-file` and the user picks
  from the library. Never guess by order or size.
- Personalized responses use `Cache-Control: no-store` and
  `Referrer-Policy: no-referrer`; request lines over 4,096 characters are
  rejected. The player fetches media from put.io; the OAuth token stays in
  Engine.

### Videos put.io must convert

`ResolvePlayback` never converts. Only GET on selected media, status URLs
included, calls `StartPlaybackConversion`, once per resolution. A selected
download keeps waiting as above; a library or owned row
[waits](#videos-already-in-putio), asking again on each read that still finds
the video unconverted. A video put.io can't convert plays `unavailable`.

The library's convert row selects
`/s/<credential>/play/movie/chill:file:<fileId>/owned:<fileId>.m3u8`; both IDs
must name the same file. Neither convert nor preparing rows carry subtitles,
and a video that becomes ready during the wait plays without them; reopen it
from the library to get them.

## Episode releases

Episode rows come from `Search` for the show title and `SxxEyy`. A row is
dropped only when Engine's release info names another season or an episode
range without the requested one; the adapter never parses release names.
Selecting by play URL still finds any search result.

## Season packs

An episode's list ends with one **Download season to put.io** row when
`GetTVShowSeasonDownloads` offers a pack. After the episode rows are ready the
listing waits up to 0.5 seconds more, or until 5 seconds after the request; a
slower, failed or refused lookup drops the row, so a cold first visit can miss
it. Selecting it resubmits only while Engine offers the same pack, else
`release-unavailable`. On completion the adapter plays the one non-sample video
whose Engine release info is the selected episode; otherwise `select-file`, or
`unavailable` without videos.

## Videos already in put.io

Movie and episode lists start with up to ten **Play from put.io** rows from
`FindOwnedVideos` (title and year; for episodes also season and episode).
Engine matches filenames strictly; the adapter never reads them. The listing
waits up to 0.5 seconds after release rows, or until 2 seconds after the
request. Selecting `/s/<credential>/play/<type>/<id>/owned:<fileId>.m3u8`
calls only `ResolvePlayback` and never submits. A malformed file ID, or an
`<id>` that is neither the page's ID nor the same file's `chill:file:<fileId>`,
gets `400`.

- **Waiting.** While put.io prepares or must convert the video, an HLS
  selection reads again every 5 seconds until its 25-second window, measured
  from the request's start, ends, then redirects to the same URL with the next
  `wait=<n>`. After four minutes across the player's retries, or at the fifth
  redirect, it plays `preparing`; selecting it again waits again. Legacy `.mp4`
  plays `preparing.mp4` at once.
- **Wait memory.** The adapter remembers when each wait began, keyed by a hash
  of the credential and selection, until 60 seconds after its last request.
  Past 256 entries a joining wait first forgets the least recently seen entry
  idle for over 35 seconds; it never evicts an active wait. A restart forgets
  every wait, so a deploy more than about 90 seconds into a Stremio Web wait
  ends it with a player error; select the row again.
- **Engine failures.** While a selection waits, `resource_exhausted`,
  `unavailable`, `deadline_exceeded` or `unknown` (including a failed
  connection) hold the rest of the window. Elsewhere on a first read they
  return `5xx`, which Stremio Web retries; a gone or unplayable file plays
  `unavailable` and a rejected credential `reconnect`.

Misses (open these from the library): filenames without a year, alternate
titles, years off by one, date or absolute episode numbering, multi-episode
files, folder-named videos, results past put.io's first 100, underscore-joined
names, files put.io types as plain files, shared files, season 0. It can also
match a different title with the same name and year.

## Clients

Stremio Web (pinned client, Chromium) and Stremio for Linux are supported;
manifests and `/configure` call other apps unverified.

- Web with a connected streaming server transcodes through it; no lane covers
  that path.
- Android clients' ExoPlayer read timeout (8 seconds) is shorter than a pending
  hold, so waiting there is unsupported, including on owned rows put.io is
  still preparing.

## Release

```sh
mise run verify
mise run hosted:smoke
docker build -t chill-stremio:release-candidate .
mise run hosted:container
```

- `hosted:smoke` drives the pinned Web client against a fake Engine
  ([hosted-fixture.ts](../harness/hosted-fixture.ts)); its recording is
  shareable only because the lane is fake. Read its structured receipt before
  claiming playback or cleanup. Its owned-wait step selects a fake
  **Play from put.io** library row that is still preparing: the player must
  keep loading through a `wait=1` redirect and a manifest retry, never request
  the `preparing` clip, and decode once the fake reports it ready, calling only
  `ResolvePlayback`. No lane covers the wait on the Convert row or live.
- `hosted:container` runs the image read-only with no capabilities and checks
  the credential never reaches container logs.
- Releasing commits on `main` cut a semantic-release version.
  [Publish hosted adapter](../.github/workflows/publish-hosted.yml) is manual
  and main-only: `build` verifies, tests and pushes the image to GHCR;
  `publish` runs in the `publish` Environment with no checkout and no token
  permissions, records the digest and dispatches Engine's deploy; `canary` runs
  `hosted:public`.
- Rollback: dispatch Engine's deploy with an earlier digest. Any v2.0.3+ image
  works; v2.0.0–v2.0.2 reject every issued link. Releases older than the canary
  fail their canary job; dispatch the canary from `main` instead.
- The `chill-stremio` package must grant `chill-engine` read access in its
  Actions access settings; GitHub has no API for it.

### Canary credential

[canary.yml](../.github/workflows/canary.yml) runs `hosted:public` in the
`canary` Environment, which admits only `main` and holds
`CHILL_STREMIO_CREDENTIAL`. Keep repository and organization secrets out of
this repo; the canary runs repository code. `hosted:public` consumes no stream.

Mint with the designated account's [environment](./live.md#setup):

```sh
credential="$(mktemp)"
mise run hosted:credential > "$credential" &&
  gh secret set CHILL_STREMIO_CREDENTIAL --env canary -R chill-institute/chill-stremio < "$credential"
rm -f "$credential"
```

- The task writes only to a pipe or a `0600` file and refuses a terminal; the
  temp file stops a failed mint from storing an empty secret.
- Engine answers `409 download_folder_missing` until the account has a
  download folder.
- Rotate after any exposure, before Engine retires the signing key, or when the
  canary reports `Engine rejected the credential`: choose **disconnect
  Stremio** at `https://chill.institute/stremio` as the designated account,
  then mint again.
- A `season-downloads` or `owned-videos` failure means Engine does not grant
  that RPC to add-on credentials; a new credential won't fix it.
